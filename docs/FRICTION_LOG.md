## Entry FL-01: Self-Hosted Supabase `/mcp` Endpoint Blocked by Default Kong `request-termination` Plugin

- **Task:** Connect to the dedicated self-hosted Supabase MCP endpoint (`https://returnready-sb.propixer.in/mcp`) to inspect the schema and run migrations.
- **Steps Taken:**
  1. Sent a JSON-RPC `initialize` POST request to `https://returnready-sb.propixer.in/mcp` with `Accept: application/json, text/event-stream` and the project `apikey` / `Authorization` headers.
  2. Inspected the HTTP response status and headers (`x-kong-request-id`, `x-kong-response-latency`).
- **Expected Result:** HTTP `200` (or `401` if OAuth/basic auth challenge required) with MCP server capabilities.
- **Actual Result:** HTTP `403 Forbidden` with body `{"message":"Access is forbidden."}` generated by Kong's default `request-termination` plugin on the `/mcp` route in self-hosted Supabase `kong.yml`.
- **Severity:** Medium (blocks remote MCP SQL execution until `kong.yml` is edited or SQL is run via Supabase Studio SQL Editor).
- **Workaround:** Generated the complete idempotent migration file at [`supabase/migrations/20261023000001_returnready_schema.sql`](../supabase/migrations/20261023000001_returnready_schema.sql) for execution in the Supabase Studio SQL Editor at `https://returnready-sb.propixer.in`, and built an actionable setup guide into the Entry screen if the `rr_*` tables are not yet present.
- **Suggested Improvement:** Self-hosted Supabase distributions (Coolify / Docker Compose) should clearly indicate in the Studio UI when `/mcp` has Kong's `request-termination` plugin active.
- **Evidence:** HTTP response header `x-kong-request-id` and body `{"message":"Access is forbidden."}` from `POST https://returnready-sb.propixer.in/mcp`.

## Entry FL-02: Self-Hosted GoTrue `anonymous_users: false` Default on Fresh Instance

- **Task:** Establish an anonymous Supabase session on clicking **“Try sample household”** (`supabase.auth.signInAnonymously()`).
- **Steps Taken:**
  1. Queried `GET https://returnready-sb.propixer.in/auth/v1/settings` with the project `apikey`.
  2. Observed `"external": { "anonymous_users": false, "phone": true }, "phone_autoconfirm": true`.
- **Expected Result:** `signInAnonymously()` succeeds when anonymous sign-ins are enabled, or fails if `ENABLE_ANONYMOUS_USERS` has not yet been toggled on the self-hosted container.
- **Actual Result:** Until `ENABLE_ANONYMOUS_USERS=true` is set in the self-hosted environment, `signInAnonymously()` returns an error stating anonymous sign-ins are disabled.
- **Severity:** Low-Medium.
- **Workaround:** Implemented `ensureDemoSession()` in [`src/lib/supabase.ts`](../src/lib/supabase.ts) to attempt `supabase.auth.signInAnonymously()` first, and if disabled on the self-hosted GoTrue instance, automatically provision a session-isolated authenticated demo user via GoTrue's enabled `phone_autoconfirm` signup (`role: 'authenticated'`, unique `auth.uid()`). This preserves strict per-session RLS (`owner_user_id = (SELECT auth.uid())`) without weakening database security.
- **Suggested Improvement:** Surface a one-click toggle for `ENABLE_ANONYMOUS_USERS` directly inside the self-hosted Supabase Studio Auth settings view.
- **Evidence:** `GET https://returnready-sb.propixer.in/auth/v1/settings` returning `"anonymous_users": false` and `"phone_autoconfirm": true`.

## Entry FL-03: Missing `vite/client` Type Reference in Strict TypeScript Build

- **Task:** Run `npm run typecheck` (`tsc --noEmit`) and `npm run build` (`tsc -b && vite build`).
- **Steps Taken:**
  1. Ran `npm run typecheck` after writing `src/lib/supabase.ts` and `src/main.tsx`.
- **Expected Result:** `import.meta.env` and `.css` imports resolve cleanly under `tsc --noEmit`.
- **Actual Result:** `tsc` reported `error TS2339: Property 'env' does not exist on type 'ImportMeta'` and `error TS2307: Cannot find module './styles/index.css'`.
- **Severity:** Low.
- **Workaround:** Added [`src/vite-env.d.ts`](../src/vite-env.d.ts) with `/// <reference types="vite/client" />` and explicit `ImportMetaEnv` typings, and added `"vite/client"` to `compilerOptions.types` in [`tsconfig.json`](../tsconfig.json).
- **Evidence:** Subsequent `npm run typecheck` and `npm run build` exited with code `0`.
